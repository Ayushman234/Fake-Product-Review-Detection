# 🔍 Fake Product Review Detection System

A machine learning project that detects whether a product review is **Fake** or **Genuine** using Natural Language Processing (NLP), TF-IDF Vectorization, and Logistic Regression.

---

## 📋 Overview

Online fake reviews are a growing problem that misleads consumers and damages trust in e-commerce platforms. This project builds a binary classifier that can automatically distinguish between computer-generated fake reviews and authentic human-written reviews.

## ❓ Problem Statement

With the rise of e-commerce, fake product reviews have become increasingly prevalent. These fabricated reviews can:
- Mislead consumers into purchasing low-quality products
- Unfairly boost or damage product ratings
- Undermine trust in online marketplaces

This project addresses this problem by building an automated detection system.

## 🎯 Objective

Build a machine learning model that:
- Takes a product review as input
- Processes it using NLP techniques (text cleaning, lemmatization, TF-IDF)
- Classifies it as **Fake** or **Genuine**
- Achieves **>87% accuracy** using Logistic Regression

## ✨ Features

- **Advanced Text Preprocessing**: Automated cleaning including lowercase, URL/HTML removal, punctuation stripping, and **lemmatization** (NLTK WordNetLemmatizer)
- **TF-IDF Vectorization**: Converts text into numerical features using Term Frequency-Inverse Document Frequency
- **Logistic Regression**: Simple, interpretable, and effective classification
- **Exploratory Data Analysis**: Visualizations of class distribution and review characteristics
- **Interactive CLI**: Enter reviews and get instant predictions
- **Streamlit Web App**: User-friendly web interface for review detection
- **Model Persistence**: Save and reload trained models without retraining

## 🔧 Data Preprocessing

The preprocessing pipeline (`src/preprocess.py`) performs the following steps:

### Dataset-Level Steps
1. **Column Validation**: Ensures expected columns exist in the CSV
2. **Missing Values**: Drops rows with missing review text or labels
3. **Duplicate Removal**: Removes duplicate reviews (keeps first occurrence)
4. **Label Validation**: Keeps only rows with valid `CG` or `OR` labels
5. **Empty Review Removal**: Drops reviews that become empty after cleaning
6. **Label Mapping**: `CG` → Fake (1), `OR` → Genuine (0)

### Text Cleaning Steps (applied per review)

| # | Step | Example | Purpose |
|---|------|---------|---------|
| 1 | **Lowercase** | `"AMAZING"` → `"amazing"` | Uniform casing |
| 2 | **Remove URLs** | `"http://x.com"` → `""` | Remove noise |
| 3 | **Remove HTML tags** | `"<b>great</b>"` → `"great"` | Remove markup |
| 4 | **Remove punctuation** | `"great!!!"` → `"great"` | Clean tokens |
| 5 | **Remove extra whitespace** | `"great  product"` → `"great product"` | Normalize spacing |
| 6 | **Stopword removal** | `"this is a great"` → `"great"` | Remove ~180 uninformative words |
| 7 | **Lemmatization** | `"running"` → `"run"`, `"products"` → `"product"` | Reduce inflections to base form |

> **Why Lemmatization?** TF-IDF treats "run", "runs", "running", "ran" as 4 separate features. Lemmatization collapses them into one ("run"), reducing vocabulary noise and helping the model generalise better.

> **Why Stopword Removal?** Common words like "the", "is", "and" appear in virtually every review and carry no signal for fake vs genuine classification. Removing them lets TF-IDF focus on discriminative words.

## 📝 TF-IDF Vectorization

Term Frequency-Inverse Document Frequency (TF-IDF) converts review text into numerical feature vectors:

| Parameter | Value | Rationale |
|---|---|---|
| `max_features` | 15,000 | Captures sufficient vocabulary without excessive dimensionality |
| `ngram_range` | (1, 2) | Captures both single words and two-word phrases |
| `min_df` | 2 | Ignores very rare terms (appear in <2 documents) |
| `max_df` | 0.95 | Ignores very common terms (appear in >95% of documents) |
| `sublinear_tf` | True | Applies logarithmic TF scaling to reduce impact of term frequency |

**Important**: TF-IDF is fitted **only on training data** to prevent data leakage. Test data is only transformed.

## 🤖 Logistic Regression

Logistic Regression is used because:
- Simple and interpretable
- Works well with high-dimensional sparse data (TF-IDF features)
- Provides probability estimates for predictions
- Fast to train and predict

| Parameter | Value |

## 🏋️ Model Training

The training pipeline (`src/train.py`):

1. Loads and preprocesses the dataset (with lemmatization)
2. Performs EDA with visualizations
3. Splits data 80/20 (stratified, random_state=42)
4. Applies TF-IDF vectorization (fit on train only)
5. Trains Logistic Regression
6. Runs 5-fold cross-validation
7. Evaluates on test set
8. **If accuracy < 87%**: Automatically tunes hyperparameters using GridSearchCV
9. Saves model, vectorizer, confusion matrix, and metrics

## 📈 Evaluation

The model is evaluated using:

- **Accuracy**: Overall correct predictions
- **Precision**: Of reviews predicted as Fake, how many are actually Fake
- **Recall**: Of actual Fake reviews, how many were detected
- **F1-Score**: Harmonic mean of precision and recall
- **Confusion Matrix**: Visual breakdown of TP, TN, FP, FN

## ⚠️ Limitations

- **Dataset-specific**: Trained on the Kaggle Fake Reviews Dataset; may not generalise well to all types of fake reviews
- **Text-only**: Only uses review text; does not consider reviewer behaviour, timing, or metadata
- **Computer-generated focus**: The dataset contains computer-generated fakes, which may differ from human-written fake reviews
- **Language**: Only works with English reviews
- **Single algorithm**: Uses only Logistic Regression; ensemble methods may perform better
